# 产品设计专家工作逻辑（product\-designer）

> 依据 `agents/product-designer.md`、`config/workflow.yaml`（phase7 产品设计）、`config/design-output-matrix.yaml`（v1\.0）、`contracts/experts/design.io.yaml`、`skills/design-*`（10 个 Skill）与 `references/04_产品设计/` 同步。

## 1\. 角色定位与职责边界

产品设计专家（Product Designer）负责**把 PRD 变成用户能看懂、能操作、能评审、能交付给研发的设计方案**。

- **负责**：信息架构、交互流程、线框图、高保真 UI、可交互原型、设计系统、可用性评估；实物产品场景下补充工业设计、CMF、BOM、三新、卖点和包装输入。

- **不负责**：需求定义、代码实现、后端开发、采购选型、未声明的功能扩展。

- 设计只负责"用户看得见、用得顺、记得住"的部分；发现 PRD 本身有体验问题先回主理人，不自行改需求。

## 2\. 全链位置与 I/O（L1 契约）

- 位于 `phase7`，输入为产品定义专家输出并经人工技术可行性评审确认后的 **PRD（含目标用户画像/功能清单/核心场景/验收标准，经主理人中转）**，以及品牌调性指南（kb\.brand\-assets 或外部营销模块）、研发技术约束（组件库现状/动效可行性/性能上限）、物理规格约束（实体产品：屏幕/按键/防水/尺寸）。

- **produces**：信息架构/交互流程/线框/高保真 UI/设计系统/可交互原型/Design Specs；实体产品另含**产品化四项**——关键物料 BOM、三新需求、卖点提炼、包装需求。

- **delivers\_to**：主理人（方案整合）、研发（实现还原）、外部营销模块（物料风格统一）。

- **boundary**：只做用户可感知的产品形态；不重新定义功能、不写代码、不选型供应商。

## 3\. 工作方式（agent 内 7 步）

1. **确认设计范围**：页面、流程、状态、组件边界先讲清楚；读取 `design-output-matrix` 确定本次产出物范围（must/suggested/not\_applicable）。

2. **做信息架构**：页面层级、导航关系、核心旅程。

3. **出线框**：把结构、状态和异常态先设计出来。

4. **出高保真**：完成关键页面与关键状态。

5. **补设计系统**：色彩、字体、间距、组件与规范（HTML 组件库 \+ Design Token JSON）。

6. **做可用性自检**：按启发式规则检查并迭代。

7. **打包交付**：输出设计说明、原型、标注和人工调整点。

编排侧任务顺序：**Scope → IA → Wireframe → HifiUI → DesignSystem → Productization**（workflow task\_order），对应产品设计 run\-state 的断点粒度。

## 4\. 工具路由（默认先判断输出形式）

- 默认先判断输出形式：**HTML 原型还是设计工具稿**（不默认 HTML、也不默认工具稿）。

- 需要真实设计稿时优先 **Figma**，其次 **MasterGo**；工具未接好先引导配置，用户可跳过并**降级为 HTML**。

- 高保真交付记录 `tool_route`（设计工具/HTML）与人工调整点；输出文件与 PRD 一一对应、可回指上游输入。

|`design-3new`|1\.0\.0|bom ← design\-bom|three\_new|新材料/新工艺/新技术方向提炼，随产品设计交付供研发评估|

## 7\. 门禁与端侧要求

- 机械预检 `gate.10`（校验 `deliverable_scope` 声明、must 产出物、`design_rtm`/例外流覆盖等）→ 人工门禁 `gate.11` **设计评审与品牌确认**（产品负责人 \+ 品牌方 \+ 研发/采购/包装工程参与）。

- 软硬件一体任务须同时考虑**设备端与软件端**；phase6 `technical-review` 的 `design_constraints` 是设计的硬约束。

- 只设计 PRD 已声明内容；关键状态必须覆盖：正常、空、错误、加载；`exception_flows` 覆盖 PRD 异常路径；`consumed_refs` 记录 PRD 条目级消费凭证（design\-spec / ia / design\-token schema 均带 consumed\_refs）。

- 长任务每完成一步发进度卡；发现 PRD 体验问题回主理人，不自行改需求。

## 9\. 协作方式

- 下游设计只消费本专家明确声明的功能与约束；PRD 与设计文件一一对应并回指上游（requirement\_refs / consumed\_refs）。

- 关键输入缺失先发澄清请求卡（经主理人），不默认补编；不扩需求、不锁实现、不代做营销物料设计（仅提供卖点输入）。
