# 调试与可靠性领域指南

> 岗位职责与任职资格见 [《数字岗位与能力模型》](../01-数字组织与岗位/03%20数字岗位与能力模型.md)。本文只描述**调试与可靠性专业工作怎么做**。

## 1. 领域定位

调试与可靠性负责把异常从现象、时间线、假设和实验推进到可证实 Root Cause，并定义最小修复和回归边界。具体平台事实仍由 BSP/MCU/Driver 等领域 Owner 提供。

## 2. 典型任务

现场偶发、长稳异常、Crash/HardFault、Memory Corruption、Deadlock/Race、DMA/Cache、Storage 异常、性能退化、资源增长和跨多个专业的 Root Cause 收敛。

诊断类任务的路由和 Mode 只在 [任务类型运行矩阵](../03-流程与运行/05%20任务类型运行矩阵.md) 维护。

## 3. 必要输入

- exact source / firmware / device；
- 现象、时间、概率和环境；
- 完整前后文日志/trace/core/dump/register；
- 最近变更和版本差异；
- 原复现步骤；
- 性能/长稳趋势数据（如适用）；
- 相关领域 Owner 已确认的直接事实。

## 4. 分析方法

```text
冻结 Context
→ 建时间线
→ 区分 Observed / Inferred / Confirmed
→ 维护一份 Hypothesis Registry
→ 设计 discriminating experiment
→ reject / support / confirm
→ Root Cause 或 evidence insufficient
→ 最小修复建议
→ regression / stress / failure injection
```

好的 Hypothesis 必须可证伪、有 evidence_for/evidence_against，并说明实验结果如何区分候选。坏例子是“系统不稳定”“可能硬件问题”这类无法直接验证的描述。

常用模型：Crash/HardFault 看 fault context + ELF/map + task/ISR；Memory Corruption 看 OOB/UAF/double free/stack/DMA ownership/cache/concurrency；Deadlock 看 wait-for graph + lock order + priority；Storage 按 media/ECC→MTD→UBI→FS→app；Performance 按 baseline→measurement→bottleneck→change→remeasurement。

## 5. Evidence 要求

Root Cause 至少要求：能解释主要现象、与版本/平台差异一致、有区分其他候选的 evidence、修复或故障注入按预期改变结果，并能由 Verification 独立复核。

“跑了一夜没出现”“改后暂时不出现”只能说明当前样本未复现，应保持 supported/workaround，不能单独写成 confirmed root cause。

## 6. 输出

Timeline、Hypothesis Registry、Root Cause / `evidence insufficient`、Engineering Recommendation、Regression Scope、Residual Risk 和 Knowledge Candidate。

## 7. 协作与交接

- P03/P04/P05：提供平台、MCU、Driver 的直接专业事实；
- P02：处理系统级职责或资源假设；
- P01：收敛 Technical Decision 和后续 Engineering；
- Engineering：只修改已确认的最小责任点；
- P07：独立复核修复证据和回归；
- P08：审查 residual risk 和错误放行风险。

## 8. 常见错误

- 只看最后一条 error，不找第一个异常点；
- 先认定根因，再只搜支持证据；
- 不同专业维护多份互相矛盾的 RCA；
- 一次改变多个关键变量导致无法确认因果；
- 复现版本和验证版本漂移；
- 用语言置信度代替 Evidence；
- 把 workaround 或“暂未复现”升级成 confirmed root cause。

## 9. BLOCK 条件

source/fw/device identity 不一致、关键日志只有截断片段且无法恢复上下文、复现条件未知却要求 Root Cause、需要平台事实但领域 Owner 尚未确认、区分实验无法执行且替代 Evidence 不足时，应保持 `evidence insufficient` 或 BLOCK，而不是补全猜测。
