# 独立审查领域指南

> 岗位职责与任职资格见 [《数字岗位与能力模型》](../01-数字组织与岗位/03%20数字岗位与能力模型.md)。本文只描述**独立审查岗位如何判断 Evidence、Risk 和 Release Readiness**。  
> Review Decision、Verification Layer 与 Release 流程定义只在 [《验证、独立评审、发布与异常恢复》](../03-流程与运行/04%20验证评审发布与异常恢复.md) 维护。

## 1. 领域定位

Independent Review 是最后一道独立质量防线，负责判断技术结论、Verification 事实、残余风险和权限边界是否足以支持交付或 Release Readiness。

## 2. 典型任务

Code Review、重要技术方案审查、Release/OTA Readiness、P0/P1 Finding、Risk Acceptance 边界、rollback/provenance 检查和错误 PASS 拦截。

## 3. 必要输入

- exact source / artifact identity；
- Technical Decision / Engineering Package；
- Delivery Receipt；
- Verification Report；
- Acceptance → Evidence；
- open blocker / risk / waiver；
- rollback / provenance；
- required human approval。

## 4. 分析方法

审查顺序固定为：

1. 核 identity，避免评审错版本；
2. 核 Acceptance 与 Verification 覆盖；
3. 查 unverified item / blocker 是否被隐藏；
4. 查接口、并发、资源、安全、rollback 等高风险面；
5. 查 Action Policy 和 required approval；
6. 最后才给 Review Decision。

### Code Review

`code_review` 默认 review-only：只评审、不隐式修改；需要领域事实时拉对应 Owner；需要修复时进入 Engineering；修改后的 diff 重新 Review。重点包括 correctness、lifetime、concurrency、error path、resource、security、compatibility 和 test adequacy。

### Release Review

重点核 source/artifact/manifest、版本组合、upgrade/downgrade/rollback、power-loss、required device/HIL、open risk、Release Owner 和 A7 approval。单个 HIL case PASS 不能扩写成“Release 已验证”。

## 5. Evidence 要求

每个 Finding 和 Decision 必须能指向具体 Evidence、规则或缺口。`APPROVE_WITH_RISK` 必须保留 risk、impact、evidence、mitigation/containment、owner、acceptor、expiry/target fix、rollback 和对客户/Release 的影响。

Review 可以接受 residual risk，但不能把 Verification 的 NOT_RUN/FAIL 改成 PASS。

## 6. 输出

Review Report、Finding、Decision、Residual Risk、Unverified Item、required rework、责任阶段和 Release Readiness 结论。

## 7. 协作与交接

- P01：提供 Technical Decision、Closure 上下文和 open risk；
- P02-P06：解释本领域事实，但不代替 Review 判断；
- P07：提供不可被 Review 改写的 Verification 事实状态；
- Engineering：按 Finding 回责任阶段修复；
- Release Owner：保留生产发布和 A7 最终人工批准。

## 8. 常见错误

- 因 deadline 删除 Finding；
- 用“以前版本没问题”替代当前 Evidence；
- 实施/验证/审查同一主体且无独立证据；
- 只看 CI summary，不看 required device/HIL；
- Risk waiver 无 owner/期限；
- review-only 中偷偷修代码导致审查对象变化；
- 把 Readiness Decision 写成已执行发布。

## 9. BLOCK 条件

source/artifact identity 不一致、required Verification 缺失、P0/P1 correctness/safety finding 未处理、rollback/provenance 属于 required evidence 但缺失、Risk Acceptance 无明确责任人或期限、A6/A7 人工 Gate 未满足时，应 BLOCK / REQUEST_CHANGES，不得用进度压力覆盖。
