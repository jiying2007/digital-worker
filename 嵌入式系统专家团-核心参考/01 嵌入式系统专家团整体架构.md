# 01 嵌入式系统专家团整体架构

> 同步基线：`v0.7.0 / provider-neutral`
>
> 上位架构：`研发中心AI数字员工研发流程规划.md` + ADR-003。

## 1. 定位

嵌入式系统专家团是研发中心 AI 数字员工体系中的**嵌入式软件专业技术决策与研发协作层**。它不是单一聊天机器人，也不绑定某个 Coding Agent；它由正式专家、Skill、Workflow、Gate、Contract、Schema、Evidence、Verification 和 Pilot 组成。

核心目标：

1. 任务先分类，再进入最小必要专家链；
2. 工程证据优先于模型自信度；
3. Expert Team 与 Engineering Agent Runtime 解耦；
4. Verification / Independent Review 与实施分离；
5. A5~A7 等高风险动作受授权/人工 Gate；
6. 通过真实 Pilot 决定能力扩展和 Provider 选型。

## 2. 1+7 组织

|Agent|职责|
|---|---|
|`embedded-system-team-lead`|接诊、路由、Gate、交接、恢复、收口|
|`embedded-architecture-expert`|架构、资源、接口、平台影响、可行性|
|`linux-bsp-expert`|Boot/BSP/Kernel/DT/IRQ/DMA/Storage|
|`mcu-rtos-expert`|Bare-metal/RTOS/Startup/Linker/ISR/Watchdog|
|`driver-component-expert`|驱动、外设、组件、平台适配|
|`debug-reliability-expert`|Crash/HardFault/并发/内存/性能/长稳|
|`verification-expert`|验证计划、SIL/Device/HIL/回归/证据|
|`embedded-review-governor`|独立 Review、风险与 Release Readiness|

Agent = 稳定职业角色；Skill = 可复用方法；Workflow = 固定闭环；Knowledge = 可追溯事实/规则/案例。Flash、Wi-Fi、Audio、FOC 等专项默认先 Skill 化。

## 3. Provider-neutral 总体关系

```text
Interaction / Work Item Provider
        │
     task-brief
        ▼
Embedded System Expert Team
        │
 K / M / 0 → Triage → Analysis → T → E
        │
engineering-task-package
        ▼
Engineer + Engineering Agent Runtime
        │
   delivery-receipt
        ▼
Verification → Independent Review → Closure
        │
Evidence / Identity / Audit
```

候选 Provider 例如：

- Interaction：WorkBuddy、飞书、Web、IDE/CLI；
- Work Item：飞书或其他协作系统；
- Knowledge：WeKnora 或其他检索/RAG 实现；
- Engineering Runtime：Codex、Claude Code、IDE Agent、内部 Agent；
- Knowledge/Evidence Source：飞书文档、NAS、Git、CI/HIL、Artifact Store。

这些名称是候选实现，不是总体架构依赖。

## 4. 14 类 task_type / 7 种 mode

`feature_development / defect_debugging / architecture_design / technical_feasibility_review / platform_bringup / bsp_porting / driver_development / component_development / mcu_firmware_development / performance_optimization / stability_reliability / code_review / release_ota / field_incident`。

Mode：`full_chain / short_chain / diagnostic_chain / bringup_chain / review_only / release_chain / single_expert`。

禁止默认 full-chain；mode 扩展必须显式决策。

## 6. 四条铁律

### Evidence-first
关键 claim 必须绑定 evidence；资料不足允许 `BLOCKED / INSUFFICIENT_EVIDENCE`。

### Debug 事实状态分离
`Observed / Inferred / Confirmed` 与 `open / supported / rejected / confirmed` Hypothesis Registry。

### Verification 分层
`implemented / host_verified / cross_build_verified / sil_verified / device_verified / hil_verified / release_verified` 独立记录，禁止跨层推导。

### 实施与签字分离
实现者不能给自己的最终 Verification / Review 签 PASS。

## 7. A0-A7

A0 Read、A1 Analyze、A2 Generate 默认允许；A3 Modify Worktree / A4 Build Test 受控；A5 Device Read 需授权；A6 Device Write / A7 Release 需人工批准。权限不会因为 Runtime Provider 不同而改变。

## 8. Knowledge / Runtime / Work Item 边界

- Source of Truth stays at source；
- Knowledge Provider 统一访问但不自动取得原文权威；
- NAS/Git/CI/HIL 等强版本事实按 exact ref/hash/revision 使用；
- Expert identity 与模型/Runtime identity 分离；
- Work Item Provider 不得绕过 Expert/Gate/Action Policy。

## 9. 当前成熟度

`architecture-frozen + provider-neutral + pilot-operations-ready`。

这不代表 Provider 已选定，也不代表 real Pilot 已完成，更不代表 Production Ready。
