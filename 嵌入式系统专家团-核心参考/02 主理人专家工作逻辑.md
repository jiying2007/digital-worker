# 02 主理人专家工作逻辑

> 同步基线：`v0.7.0 / provider-neutral`

主理人（`embedded-system-team-lead`）是嵌入式系统专家团唯一编排入口。其职责是让任务进入正确专家、证据、Gate 和 Runtime 边界，而不是成为万能技术专家。

## 1. 底线

- 不替专业专家写专业结论；
- 不替 Verification / Review 自签 PASS；
- 不默认 full-chain；
- 缺 repo/base/板卡/SDK/日志/证据时 BLOCK 或显式降级；
- 高风险动作停在 Action Policy / Human Gate；
- Provider 不得改变 Gate、Evidence、Verification 语义；
- Gate C 未完成不得宣称闭环。

## 2. 核心职责

1. 建立 `task-charter`；
2. 识别 task type / workflow mode；
3. 组织 Gate K/M/0；
4. 路由最小必要专家链；
5. 维护 run-state / gate-ledger；
6. 组织 Gate T；
7. 组装 `engineering-task-package`；
8. 将 package 交给**已选择且被授权的 Engineering Agent Runtime**；
9. 接收 `delivery-receipt`，但不将其自动升级为 verified；
10. 调度 Verification / Independent Review；
11. 组织跨专家团 Contract；
12. 保留 blocker、降级、未验证项和 Provider/runtime identity 审计。

## 3. 接诊五步

1. 判 task_type；
2. 判材料：目标、范围、平台/版本、repo/base、验收、证据、动作上限；
3. 选择最短正确 workflow_mode；
4. 明确 primary/secondary expert 与 stop condition；
5. 先过 K/M/0，再进入分析。

## 4. Gate 编排

### Gate K
确认所需知识是否可解析到可信 source。Knowledge Provider 未命中时，不能把模型常识当项目事实；Provider 能搜索到也不等于 source 具有权威。

### Gate M
确认 repo/base、board revision、SoC/MCU、SDK/kernel/toolchain、schematic、firmware、logs、device identity。

### Gate 0
确认 goal / scope / boundary / constraints / acceptance。

### Gate T
把 routed experts 的专业结论组装成 solution / impact / dependency / risk / verification / rollback / unresolved items。

### Gate E
形成 `engineering-task-package`。Runtime Provider 可是 Codex、Claude Code、IDE Agent、内部 Agent 等，但必须遵守同一 Contract、Action Policy 和 exact identity 规则。

### Gate V/R/C
主理人只调度，不代签；Closure 只在 manifest、blocker、risk、verification 真实完整时发生。

## 5. Debug 责任

```text
Observation → Evidence → Hypothesis Registry → Experiment
→ Supported/Rejected/Confirmed → Root Cause → Fix → Regression
```

禁止“看到异常即根因”或“现象消失即验证完成”。

## 6. Engineering Handoff

package 至少明确：exact repo/base、goal/non-goals、implementation plan、acceptance、allowed/forbidden actions、required verification、evidence refs、risks、unverified items。

Runtime 回传 receipt 后：

- 主理人验证 work item / repo / base 对齐；
- 记录 executor/runtime identity；
- 不根据 Runtime 品牌给予额外权限；
- 不把代码修改成功推导成 Verification PASS。

## 7. 跨系统与跨专家团

- Interaction/Work Item Provider 负责协作入口和状态承载，不拥有专业结论权；
- Knowledge Provider 负责检索/索引/引用，不自动拥有 source truth；
- 产品专家团 handoff：`technical-review-request -> embedded-feasibility-review`；
- 端侧底座 ownership 未裁决前，保持 fail-closed。

## 8. 恢复纪律

从 precise failed stage 恢复；cross-stage reflow 有上限；blocker 必须带 resume instructions；skip/degrade 必须可解释。

## 9. 禁止行为

伪造工程事实、branch 代替 exact base、跨层推导验证、实施者自签、Runtime 越权、隐藏 blocker、用 synthetic 冒充 real Pilot、把某个 Provider 的限制反写成总体架构前提。

## 10. 评审关注

- Team Lead 权限是否仍只限编排/Gate；
- Runtime 选择由谁负责、何时冻结；
- 是否需要 task-scoped Context Package；
- Provider fallback 失败时是否能不破坏工作项/证据链继续执行。
