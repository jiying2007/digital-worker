# 责任模型总览

本页定义核心参考中的责任语言。机器权威是 `domains/edge-foundation/domain.yaml`；本页只做人类解释，不创建第二份组织 SSOT。

## 1. 领域边界

Edge Foundation Domain 当前正式 Domain Experts 只有三个：

- **Structure Expert**（`structure-expert`）：结构与机械相关专业责任；
- **Hardware Expert**（`hardware-expert`）：硬件、电气、器件与板级专业责任；
- **Embedded System Expert**（`embedded-system-expert`）：Linux / RTOS / MCU / Driver / Debug 等嵌入式软件专业责任。

**Edge Coordination**（`edge-coordination`）是跨任务协调 Role，负责接单、材料准备度、路由、Gate、交接与 Closure；它不是第四个 Expert。

## 2. Embedded System Expert 的内部组织方式

Embedded System Expert 通过 5 个 Capability 组织专业能力：

| Capability | 责任边界 | 典型问题 |
|---|---|---|
| `embedded.architecture` | 系统边界、接口、资源、质量属性、平台影响 | 架构设计、可行性、跨仓接口、资源预算 |
| `embedded.linux-bsp` | Boot、Kernel、DT、IRQ/DMA、Storage、Power、BSP | 启动、UBI/UBIFS、DMA/cache、Bring-up |
| `embedded.mcu-rtos` | Startup、Linker、ISR/DMA、RTOS、Watchdog、MCU OTA | HardFault、ROM/RAM、并发、实时性 |
| `embedded.driver-component` | Driver、Protocol、Adapter、Stable API、器件替代 | 驱动集成、组件化、兼容矩阵 |
| `embedded.debug-reliability` | Timeline、Hypothesis、RCA、长稳、性能与故障分析 | Crash、内存、死锁、现场故障、性能退化 |

Capability 是责任组织单元，不是 Agent、Worker 或岗位。实际 Runtime 可以用一个或多个 Agent/Session 承载同一 Capability，也可以由人完成。

## 3. Assurance 独立于 Embedded Capability

可信保障平面包含：

- **Verification**：Acceptance → required layer → direct Evidence；
- **Independent Review**：按阶段和风险独立检查证据、Finding 与 Release Readiness；
- **Evidence**：保持对象 identity、来源、hash、Source-of-Truth 边界；
- **Evaluation**：维护 Golden Case、回归和质量基线。

它们不是 `embedded.*` Capability，也不能因为由同一个 Runtime 执行就改变责任归属。当前 iterative Pilot 若 Independent Review 不可用，可由 static checks + Hosted CI + traceable Verification evidence 满足 completion；这不等于 Review PASS 或 Release Approval。

## 4. 四个稳定平面

```text
Responsibility Plane  谁对专业结论负责
Orchestration Plane   任务如何分解、路由和恢复
Execution Plane       人与 Runtime 如何实际执行
Assurance Plane       如何独立证明、阻断错误 PASS、控制发布风险
```

Expert 数、Worker 数、Session 数、Skill 数互不等价。

## 5. Canonical machine authority

- Domain / Expert / Capability / Assurance：`domains/edge-foundation/domain.yaml`
- Canonical routing：`domains/edge-foundation/routing.yaml`
- Runtime task/mode policy：`domains/edge-foundation/runtime/task-modes.yaml`
- Workflow：`domains/edge-foundation/runtime/workflow.yaml`
- Skill ownership + physical path：`domains/edge-foundation/skills.yaml`
- Gate ownership：`domains/edge-foundation/gate-policy.yaml`
- Golden Cases：`domains/edge-foundation/evaluation/golden-cases.yaml`
- Product readiness：`scripts/evaluate_edge_foundation_product_readiness.py`

当前 Edge Foundation 已是 canonical execution authority；Product readiness 独立于 routing authority。Feature real Pilot 已提供 1 条 eligible receipt，Debug 与 Review/Release 仍等待真实产品 Evidence，因此产品成熟度仍诚实保持 BLOCKED。
