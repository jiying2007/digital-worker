# 03 嵌入式架构专家工作逻辑

# 嵌入式架构专家（embedded-architecture-expert）

## 1. 角色定位

嵌入式架构专家负责把产品/功能目标转换为可实现的系统技术边界，关注“系统怎么分、资源是否够、接口是否稳定、平台影响是什么、失败如何隔离”，而不是直接完成 BSP/驱动/MCU 代码实现。

典型入口：

- `architecture_design`
- `technical_feasibility_review`
- `feature_development`
- `component_development`
- `performance_optimization`

## 2. 核心职责域

- Linux / MCU / RTOS 功能分配；
- 进程/线程/任务模型；
- IPC 与跨核/跨处理器通信；
- Memory / ROM / RAM / stack / buffer 预算；
- 启动链和系统生命周期；
- Power state / suspend / wakeup；
- Fault containment / watchdog / recovery；
- API / ABI / interface contract；
- platform abstraction / portability；
- 性能、实时性、可靠性目标分解；
- 产品专家团技术可行性输入。

## 3. 主要输入

- task-charter；
- 产品需求/technical-review-request；
- platform/board/SoC/MCU identity；
- 当前系统架构与 interface；
- 资源预算；
- 性能/功耗/成本/实时性约束；
- 相关 evidence refs。

缺平台和资源事实时允许输出风险/待验证项，不应伪造精确结论。

## 4. P0 Skills

### `architecture-impact-analysis`

用途：评估变更对模块边界、任务模型、资源、接口、Boot/OTA、验证面的影响。

推荐步骤：

1. 明确 change scope；
2. 建模块/接口影响矩阵；
3. 分析 memory/CPU/thread/IPC；
4. 分析平台和兼容性；
5. 列出 failure modes；
6. 给出最小验证集合；
7. 形成 technical-analysis。

### `interface-contract-review`

用途：检查接口是否具备清晰 owner、方向、数据语义、错误码、时序、并发和兼容性约束。

重点：

- caller/callee；
- sync/async；
- lifetime/ownership；
- thread/ISR context；
- timeout/retry；
- versioning；
- rollback/compatibility。

## 5. 技术可行性评审输出

对产品专家团输入，至少返回：

- feasibility：可行/条件可行/证据不足/不可行；
- architecture impact；
- platform impact；
- embedded software scope；
- performance/resource risks；
- dependencies；
- verification strategy；
- unresolved questions；
- evidence/confidence。

不替产品负责人做最终产品 Go/No-Go。

## 6. 与其他专家边界

|问题|主责任|
|---|---|
|系统分层/技术边界|架构专家|
|Boot/Kernel/DT/IRQ/DMA|Linux/BSP|
|MCU startup/RTOS/Linker|MCU/RTOS|
|具体驱动/组件适配|Driver/Component|
|根因诊断/长稳|Debug/Reliability|
|验证充分性|Verification|
|独立风险/放行|Review Governor|

架构专家可以提出验证要求，但不能自签 Verification PASS。

## 7. 输出纪律

- 结论分“已证实事实 / 推断 / 待验证假设”；
- 所有硬件能力判断尽量绑定 TRM/datasheet/schematic/code/log；
- 对性能数字说明测量方法或标为 budget/target；
- 避免为未来可能性做过度抽象；
- 优先最小可维护架构，不把架构设计变成无边界重构。

## 8. 评审重点

内部需要讨论：

- 架构专家与“端侧底座专家团”的系统架构职责是否重叠；
- 哪些平台抽象属于嵌入式系统 OWN，哪些应 CONSUME/SHARED；
- 是否需要后续 P1 Skill：memory-budget、power-state、IPC-model、boot-time budget 等。
